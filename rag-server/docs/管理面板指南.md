# RAG 控制台使用指南

本文档介绍 rag-server 内置的 **RAG 控制台**（Streamlit Dashboard）：它是什么、如何启动、整体架构，以及六个功能页面分别能做什么、怎么用。

---

## 命名说明

界面命名遵循两条原则：**一听就懂**（少用「摄取」「追踪」等技术黑话）、**成对对称**（入库侧 / 检索侧用语一致）。

| 导航名称 | 一句话说明 | 口语示例 |
|---------|-----------|---------|
| **运行概览** | 看配置、看知识库规模、看有没有运行记录 | 「先打开运行概览看一眼」 |
| **知识浏览** | 翻看已入库的文档、分块和图片 | 「去知识浏览里查一下分块」 |
| **文档入库** | 上传文件，写入知识库 | 「把这个 PDF 文档入库」 |
| **入库记录** | 每次入库的流程详情与耗时 | 「入库失败了，看入库记录」 |
| **检索记录** | 每次问答检索的流程详情 | 「检索结果不对，查检索记录」 |
| **效果评测** | 用测试集批量打分、对比历史 | 「跑一遍效果评测」 |

界面中的 **知识库** 对应技术层的 `collection`（可理解为知识库分区，默认 `default`）。

---

## 1. 控制台定位

RAG 控制台是 rag-server 的**本地 Web 运维入口**，与 MCP Server、命令行脚本并列：

| 使用方式 | 典型场景 |
|---------|---------|
| **MCP Server** | 被 Copilot / Claude / Agent 客户端调用，在线问答 |
| **命令行脚本** | `scripts/ingest.py`、`scripts/query.py` 批量或自动化 |
| **RAG 控制台** | 人工运维：入库文档、浏览数据、查记录、跑评测 |

控制台不承担「对外问答」，而是帮你**看见并管理** RAG 系统的数据与运行过程：

- 查看当前 LLM / Embedding / 检索等引擎配置
- 上传文档入库，管理已索引数据
- 浏览分块（Chunk）、元数据与关联图片
- 回放每一次入库与检索的完整记录
- 基于黄金测试集运行 Ragas 评测，对比历史结果

界面为**简体中文**；技术专有名词（LLM、BM25、ChromaDB、Top-K、RRF、Ragas 等）保留英文，便于与配置项和日志对照。

## 2. 启动方式

在 `rag-server` 项目根目录下执行（需已安装依赖并完成 `config/settings.yaml` 配置）：

```bash
# 推荐：根目录浅入口（默认 http://localhost:8501）
streamlit run dashboard.py

# 需指定端口或局域网访问时
python scripts/start_dashboard.py --port 8502
python scripts/start_dashboard.py --port 8502 --host 0.0.0.0
```

> 控制台实现代码位于 `src/observability/dashboard/`；`dashboard.py` 仅为对外启动入口，与 `agents-master/app.py` 用法一致。

启动后在浏览器打开对应地址。左侧为**页面导航**，右侧为当前页面内容。

## 3. 整体架构

### 3.1 目录结构

```
src/observability/dashboard/
├── app.py                 # 入口：页面注册与导航
├── pages/                 # 六个功能页面（各含 render()）
│   ├── overview.py        # 运行概览
│   ├── data_browser.py    # 知识浏览
│   ├── ingestion_manager.py   # 文档入库
│   ├── ingestion_traces.py    # 入库记录
│   ├── query_traces.py        # 检索记录
│   └── evaluation_panel.py    # 效果评测
└── services/              # 页面与底层存储之间的服务层
    ├── config_service.py  # 读取 settings.yaml → 配置卡片
    ├── data_service.py    # 文档 / 分块 / 图片 / 删除 / 清空
    └── trace_service.py   # 读取 logs/traces.jsonl
```

### 3.2 数据从哪里来

| 数据类型 | 来源 | 主要用途 |
|---------|------|---------|
| 引擎配置 | `config/settings.yaml` | 运行概览 |
| 向量分块 | ChromaDB（`data/db/chroma/`） | 知识浏览、文档入库 |
| 稀疏索引 | BM25（`data/db/bm25/{collection}/`） | 检索记录诊断 |
| 图片索引 | `data/db/image_index.db` + `data/images/` | 知识浏览 |
| 入库历史 | `data/db/ingestion_history.db` | 文档列表、去重 |
| 运行记录 | `logs/traces.jsonl` | 入库记录、检索记录 |
| 评测历史 | `logs/eval_history.jsonl` | 效果评测 |

入库与检索在执行时会写入 `traces.jsonl`；两个「记录」页面均读取该文件，**无需单独配置**。

### 3.3 页面关系（推荐使用顺序）

```
运行概览 ──→ 确认配置与知识库是否就绪
    │
    ▼
文档入库 ──→ 上传文件并完成索引
    │
    ├──→ 知识浏览 ──→ 核对分块、元数据、图片
    │
    ├──→ 入库记录 ──→ 排查入库各阶段耗时与异常
    │
    └──→ （通过 MCP / 脚本发起查询）
              │
              ▼
         检索记录 ──→ 分析检索、融合、重排效果
              │
              ▼
         效果评测 ──→ 用黄金测试集量化整体质量
```

## 4. 六个功能页面

### 4.1 运行概览

**作用：** 一眼看清「引擎配了什么」和「知识库里有多少数据」。

**模块：**

1. **当前配置** — LLM、Embedding、向量存储、混合检索、重排序等可插拔组件
2. **知识库规模** — 各知识库（collection）的分块数量
3. **运行记录** — `traces.jsonl` 中的记录总数

**适用场景：** 换配置后确认是否生效；demo 前快速检查环境。

---

### 4.2 知识浏览

**作用：** 只读浏览已入库的文档、分块、元数据与图片。

**操作流程：**

1. 顶部 **知识库** 下拉框选择目标 collection
2. 下方列出文档，展开可查看分块原文、元数据 JSON、图片缩略图

**危险操作：** 「清空全部数据」会删除所有索引与运行记录，需二次确认，**不可撤销**。

**适用场景：** 检查分块质量、元数据增强效果、图片关联是否正确。

---

### 4.3 文档入库

**作用：** 上传文件触发入库流水线，管理已入库文档。

**模块：**

1. **上传文件** — 选择 pdf/txt/md/docx，指定目标知识库，点击 **开始入库**
2. **已入库文档** — 列表展示并可删除

入库进度按阶段更新：完整性检查 → 加载 → 分块 → 转换 → 嵌入 → 写入。

**适用场景：** 不想写命令行时快速灌库；单文件试跑；清理错误文档。

---

### 4.4 入库记录

**作用：** 回放每一次文档入库的完整记录，用于性能分析与故障排查。

**模块：**

| 区域 | 内容 |
|------|------|
| 入库历史 | 按时间倒序的入库列表 |
| 入库流程 | 文档长度、分块数、向量数、总耗时 |
| 各阶段耗时 | 加载 / 分块 / 转换 / 嵌入 / 写入 |
| 阶段详情 | 各 Tab 展示输入输出样本与诊断提示 |

**适用场景：** 入库慢时定位瓶颈；LLM 增强是否生效；Embedding API 是否失败。

---

### 4.5 检索记录

**作用：** 回放每一次检索查询的记录（来自 MCP 或命令行）。

**模块：**

| 区域 | 内容 |
|------|------|
| 检索历史 | 支持关键词筛选 |
| 查询概览 | 问句、来源、Top-K、知识库 |
| 结果指标 | 稠密/稀疏命中、融合、重排、耗时 |
| 阶段详情 | 各路召回分块与分数对比 |

底部可选 **Ragas 单条评测**：需手动填写生成的回答后再评分。

**适用场景：** 排查「为什么搜不到」；对比 Dense vs Sparse；看重排效果。

---

### 4.6 效果评测

**作用：** 对黄金测试集批量评测，输出汇总指标与历史对比。

**模块：**

1. **评测配置** — 后端、Top-K、知识库、测试集路径
2. **填写回答**（Ragas 模式）— 为每道题提供系统回答
3. **开始评测** — 输出汇总指标与各题详情
4. **评测历史** — 最近 10 次运行对比

**适用场景：** 调 chunk_size、换 Embedding、开关 Reranker 后的回归对比。

---

## 5. 典型工作流

### 5.1 首次灌库并验证

1. **运行概览** → 确认配置，知识库为空属正常
2. **文档入库** → 上传样例文件，目标知识库填 `default`
3. **入库记录** → 确认五阶段齐全、向量数 > 0
4. **知识浏览** → 抽查分块与元数据

### 5.2 检索效果不佳时排查

1. 通过 MCP 或 `scripts/query.py` 发起几次查询
2. **检索记录** → 看 Dense / Sparse 是否有一路为 0
3. 若有召回但回答差 → 在记录详情中填 Answer 跑 Ragas，区分检索 vs 生成问题

### 5.3 策略调优与回归

1. 修改 `settings.yaml`
2. **效果评测** → 同一测试集跑两次，在 **评测历史** 中对比
3. 结合 **检索记录** 做单条 Case 定性分析

## 6. 与 MCP / 命令行的关系

| 操作 | RAG 控制台 | MCP / 脚本 |
|------|-----------|-----------|
| 文档入库 | ✅ 文档入库 | ✅ `scripts/ingest.py` |
| 在线问答 | ❌ | ✅ MCP `query_knowledge_hub` |
| 浏览分块与图片 | ✅ 知识浏览 | ❌ |
| 查看入库/检索记录 | ✅ 入库记录 / 检索记录 | 仅读 `logs/traces.jsonl` |
| 批量评测 | ✅ 效果评测 | 可调用 `EvalRunner` |

三者共用 `settings.yaml` 与数据目录；控制台上的入库/删除会立即影响 MCP 检索结果。

---

## 7. 注意事项

1. **本地服务**：默认只监听 `localhost`；局域网访问启动时加 `--host 0.0.0.0`。
2. **API 费用**：入库中的 LLM 增强、检索记录中的 Ragas、效果评测批量运行均会调用 LLM。
3. **记录上限**：列表默认最多展示 100 条，旧记录仍在文件中。
4. **清空数据**：不会删除 `settings.yaml` 和 `data/documents/` 源文件，但会清空所有索引与记录。
5. **知识库 = collection**：界面说「知识库」，配置与代码中仍使用 `collection` 字段名。
