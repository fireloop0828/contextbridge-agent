# 旅行规划模式 — 需求与架构设计

> 文档版本：v1.0  
> 更新说明：基于产品讨论定稿，作为 `agents-master` 旅行规划功能的实现依据。  
> 实现分步计划见文末「分阶段实现」；

---

## 1. 整体需求

### 1.1 产品目标

在现有 MCP ReAct 智能体应用上，增加**专用「旅行规划」模式**，使用户获得：

- **可交互的需求收集**（最多约 2 轮提问，避免连环追问）
- **真实可信**的行程内容（路程、天气、时间、可行性有工具依据）
- **可读性高**的 Markdown 攻略
- **对话内完整可见**的成品 + **一键下载 `.md`**
- 生成后可**提出修改意见**，Agent 在保留上下文基础上修订并再次全文展示与导出

### 1.2 入口与模式


| 方式      | 规则                                                     |
| ------- | ------------------------------------------------------ |
| **主入口** | 聊天框上方提供「旅行规划」按钮；点击后高亮，进入 `travel` 模式                   |
| **辅入口** | 通用聊天中，用户明确表达做攻略/规划行程/旅行计划等意图时，自动进入同一套流程（**按钮为主、聊天为辅**） |
| **扩展**  | 后续可增加其他专用功能按钮，与旅行模式并列，互不混用默认通用行为                       |


### 1.3 信息收集（Intake）

**字段（9 项，用于完整性判断）**


| 字段              | 说明                    |
| --------------- | --------------------- |
| `destination`   | 目的地                   |
| `dates`         | 出行日期或相对时间（如「下周末」）     |
| `duration_days` | 出行天数                  |
| `companions`    | 同行类型（独自/情侣/带娃/老人等）    |
| `preferences`   | 旅行偏好（人文/自然/美食/轻松/打卡等） |
| `budget`        | 预算档位                  |
| `transport`     | 大交通及当地交通方式            |
| `must_visit`    | 必去地点（可为空，但字段需有记录）     |
| `constraints`   | 禁忌、体力、忌口等约束           |


**流程规则**

1. 用户进入旅行模式或表达规划意图后，根据已有信息判断缺失项。
2. **第 1 轮**：信息不足则提问（可一次列出多个缺失项）。
3. 用户回复后，若仍缺少 **任意 3 个及以上** 字段 → **第 2 轮**提问，并附带固定说明：
  > 若无补充，我将根据你已提供的信息做推荐性规划，不确定处会标注「待核实」。
4. 第 2 轮之后或信息已足够 → 进入**生成阶段**，不再连环追问。

**Intake 数据更新（实现约定）**

- 编排层维护 `travel_intake` 字典。
- 推荐：Agent 在回复末尾输出机器可读块 `<!--TRAVEL_INTAKE:{...}-->`，由 `app.py` 用 regex + `json.loads` 合并进 session；对用户消息辅以简单 regex 抽取（目的地、X 日游等）。

### 1.4 内容质量与可信度

- **天气**：使用高德 MCP `maps_weather`，禁止无依据编造具体气温。
- **路线/距离/时长**：使用高德路线、距离、POI 类工具；文中标注来源（如「高德 · 约 X 分钟」）。
- **玩法/注意事项/本地贴士**：使用 RAG；Agent 先 `list_collections` 再选择相关 collection 调用 `query_knowledge_hub`（知识库将扩展，**不硬编码**单一旅行库名）。
- **时间语义**：使用 `get_current_time` 解析相对日期。
- 工具查不到的信息 → 标注「待核实」，不写死门票/开放时间等。
- 生成时做**可行性自检**（单日总路程、步行量、闭馆日等）。

### 1.5 交付物形态


| 要求   | 说明                                                                  |
| ---- | ------------------------------------------------------------------- |
| 格式   | **Markdown only**，不使用 HTML 攻略（`旅行规划表设计.md` 不接入本流程）                  |
| 对话展示 | 生成/改稿完成后，**完整正文**必须在对话框中展示，不能仅提示「已保存请下载」                            |
| 下载   | **服务端自动导出**：对话中出现完整攻略正文后，由服务端将正文写入 `data/outputs/`（0 Token）；该条助手消息绑定下载按钮（`.md`） |
| 改稿   | 用户提出修改 → 基于上一版全文 + intake + 工具必要时重查 → 再次全文展示 + 导出                   |

## 2. 架构设计

### 2.1 总体分层

```
┌─────────────────────────────────────────────────────────┐
│  Streamlit UI：模式按钮、高亮、聊天、全文 MD、下载按钮      │
├─────────────────────────────────────────────────────────┤
│  编排层 (app.py / travel_mode.py)：                      │
│  app_mode · travel_phase · travel_intake · 意图检测       │
│  missing 计算 · [TRAVEL_CONTEXT] 注入 · 阶段转换          │
├─────────────────────────────────────────────────────────┤
│  Agent：LangGraph ReAct + MemorySaver (thread_id)        │
│  动态 System Prompt = 通用 SYSTEM + travel-planner.md     │
├─────────────────────────────────────────────────────────┤
│  MCP 工具层                                               │
│  amap-maps · rag-server · document-export · get_current_time │
└─────────────────────────────────────────────────────────┘
```

### 2.2 技术选型


| 层级      | 技术                                                                        |
| ------- | ------------------------------------------------------------------------- |
| UI      | Streamlit（`st.button`、`st.chat_input`、`st.markdown`、`st.download_button`） |
| 状态      | `st.session_state`                                                        |
| Agent   | LangGraph `create_react_agent` + `MemorySaver` + `thread_id` 多轮           |
| 模型      | 现有 DashScope / OpenAI / Anthropic 接入                                      |
| MCP 客户端 | `langchain-mcp-adapters` → `MultiServerMCPClient`                         |
| Prompt  | `modes/travel/travel-planner.md` + 运行时拼接 `[TRAVEL_CONTEXT]`                |
| 导出      | **本地写盘**：`export_service.save_markdown_export()`（不再走 MCP `document-export`） |


### 2.3 状态机

`**app_mode**`

- `general`：默认通用智能体
- `travel`：旅行规划专用流程

`**travel_phase**`


| 阶段           | 行为                      |
| ------------ | ----------------------- |
| `intake_1`   | 解析输入，第 1 轮提问            |
| `intake_2`   | 仍缺 ≥3 字段时第 2 轮提问 + 兜底说明 |
| `generating` | 按工具链生成完整 MD + 导出        |
| `revision`   | 根据用户意见改稿，全文 + 再导出       |


**建议 `session_state` 键**

```python
app_mode: "general" | "travel"
travel_phase: "intake_1" | "intake_2" | "generating" | "revision"
travel_intake: dict          # 9 字段
intake_round: int            # 0 / 1 / 2
last_travel_plan_md: str     # 上一版全文（改稿）
last_export_path: str        # 最近导出路径
```

**阶段转换（编排层 Python 逻辑）**

```
用户进入 travel
  → intake_1
用户回复 → 更新 intake → missing < 3 ? generating : (round<2 ? intake_2 : generating)
生成成功 → revision
用户改稿 → 保持 revision，注入 last_travel_plan_md
```

### 2.4 Prompt 设计


| 文件/片段                           | 用途                                             |
| ------------------------------- | ---------------------------------------------- |
| `app.py` 内 `SYSTEM_PROMPT`      | 通用角色、RAG、导出、来源说明                               |
| `modes/travel/general_system_travel.md` + `travel-planner.md` | 旅行专用：提问规则、工具顺序、MD 模板、可信标注、交付规则                 |
| 每轮 `[TRAVEL_CONTEXT]`           | 动态注入 `phase`、`intake`、`missing`（及改稿时的上一版摘要/路径） |


**旅行模式 Prompt 应包含**

1. ROLE：先问后写，工具优先于臆测
2. INTAKE：两问规则、缺 3 字段、兜底话术
3. TOOL_PLAYBOOK：生成阶段工具调用顺序
4. OUTPUT_TEMPLATE：固定 MD 章节结构
5. DELIVERY：对话全文 = `write_markdown_document` 的 `content`

### 2.5 MCP 工具分工

#### 高德 `amap-maps`（config.json 已配置）


| 工具                                  | 旅行流程中的角色          |
| ----------------------------------- | ----------------- |
| `maps_weather`                      | **生成必调** — 目的地天气  |
| `maps_geo`                          | **生成必调** — 地址转坐标  |
| `maps_text_search`                  | **生成必调** — POI 检索 |
| `maps_search_detail`                | 按需 — POI 详情       |
| `maps_direction_walking`            | 按需 — 步行路线         |
| `maps_direction_transit_integrated` | 按需 — 公共交通         |
| `maps_direction_driving`            | 按需 — 驾车           |
| `maps_direction_bicycling`          | 按需 — 骑行           |
| `maps_distance`                     | 按需 — 多点距离 / 可行性   |
| `maps_around_search`                | 按需 — 周边餐饮等        |
| `maps_regeocode`                    | 按需                |
| `maps_ip_location`                  | 一般不用              |


**生成阶段推荐调用顺序**

1. `get_current_time`
2. `list_collections` → `query_knowledge_hub`（Agent 自选 collection）
3. `maps_weather`
4. `maps_text_search` / `maps_search_detail`
5. `maps_geo`
6. `maps_direction`_*（按 `transport`）
7. `maps_distance`（可选）
8. （无）模型不负责写盘；系统在检测到完整攻略后自动导出

#### RAG `rag-server`

- `list_collections`：列举库，由 Agent 选择（适配未来多领域知识库）  
- `query_knowledge_hub`：主检索  
- `get_document_summary`：按需查看文档概况

冲突处理：**路线、天气、距离以高德为准**；RAG 补充玩法与注意事项，并在「数据依据」中引用来源。

#### `document-export`

当前旅行模式不再依赖 `document-export` 写盘（避免重复输出与额外 Token）。
导出由服务端将对话正文写入 `data/outputs/`，并在 UI 上挂载下载按钮。

#### `get_current_time`

- 解析相对日期、季节提示

### 2.6 UI 与交付链路

1. 聊天框**上方**模式栏：「旅行规划」按钮，激活时高亮 + 提示条。
2. 流式输出：`st.markdown` 展示**完整**攻略正文。
3. 自动导出：`looks_like_travel_plan()` 通过后写盘 → 写入该条 `history[].exports`。
4. `print_message` / 流式结束后渲染 `st.download_button`。
5. 侧边栏可保留最近导出列表（现有 `exported_files` 逻辑可复用）。

### 2.7 与现有代码的关系


| 现有能力                                   | 旅行模式中的用法                                       |
| -------------------------------------- | ---------------------------------------------- |
| `create_react_agent` + `SYSTEM_PROMPT` | 旅行时拼接 `travel-planner.md`，必要时切换模式后重建 agent     |
| `process_query` + `thread_id`          | 多轮对话；每轮包装 `HumanMessage` 附带 `[TRAVEL_CONTEXT]` |
| `write_markdown_document`              | 生成/改稿后必调，`content` = 对话全文                      |
|                                        |                                                |


可选：将编排逻辑抽到 `travel_mode.py`，`app.py` 负责 UI 与调用。

## 3. 分阶段实现（不含 Skill）


| Phase     | 目标                              | 主要技术                                          |
| --------- | ------------------------------- | --------------------------------------------- |
| **0**     | `travel-planner.md` 定稿          | Markdown 文件                                   |
| **1**     | 模式按钮、状态机、context 注入             | Streamlit + `session_state` + Python          |
| **2**     | 动态 Prompt / Agent 重建            | 读 md + 字符串拼接 + `create_react_agent`           |
| **3**     | 两问 + 缺 3 字段 + 兜底                | 状态转换 + Prompt + intake 解析                     |
| **4**     | 工具链 + 全文 + 下载                   | MCP ReAct + 现有 export UI                      |
| **5**     | 改稿闭环                            | `revision` + `last_travel_plan_md` + 再 export |
| **6**（可选） | 退出模式、侧边 intake 摘要、快捷 chip、误触发降噪 | Streamlit + 后处理                               |


建议实施顺序：**0 → 1 → 2 → 3 → 4 → 5 → 6**。

## 4. 验收标准（摘要）

- 点击「旅行规划」进入模式并高亮；辅触发不误伤普通问答  
- 信息不足时最多 2 轮提问，第 2 轮含兜底说明  
- 缺 ≥3 字段时进入第 2 轮；否则进入生成  
- 生成攻略含 RAG 引用 + 高德天气/路线依据  
- 对话框可见**完整** Markdown，且可下载同名 `.md`  
- 用户改稿后得到修订全文与新下载
