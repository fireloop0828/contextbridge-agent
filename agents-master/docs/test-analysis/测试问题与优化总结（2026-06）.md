# 旅行模式测试问题与优化总结（2026-06）

> 更新日期：2026-06-16  
> 范围：旅行模式（Streamlit UI + travel 状态机 + MCP 预取 + 自动导出 + 记忆流水线）  

---

## 1) 归档/记忆：点击卡顿与「LLM 精炼摘要」保留

### 问题概括
- 「新对话（归档当前）」触发归档时同步跑 LLM 记忆判断与摘要，导致页面卡顿；但该能力本身有价值，希望保留。

### 修复/优化路线
- fast 归档路径：先**写盘归档 JSON + 清空 latest**（立刻返回 UI）。
- 后台线程：再跑**完整记忆流水线（含 LLM worthy_kinds + session_summary）**，不阻塞 UI。
- UI 文案：提示“后台进行记忆整理”，降低用户误解。

### 使用的技术
- **后台线程**：`threading.Thread(daemon=True)` 异步执行 `run_memory_pipeline(skip_llm=False)`。
- **记忆分层**：规则预筛 + LLM 判断拆开，按触发点（archive / travel_export）走不同耗时策略。

---

## 2) 导出/下载：过早导出、导出失败、完整攻略必有下载按钮

### 问题概括
- intake/POI 阶段误生成 md（或 LLM 工具输出 path 被误识别）。
- 完整攻略生成后偶尔无下载按钮（检测逻辑被标题 emoji / 后处理影响）。

### 修复/优化路线
- 导出门槛：只在**确认完整攻略**时导出（结构检测），intake/POI 一律不导出。
- 导出输入：导出前先**剥离 intake 确认话术前缀**，再写盘。
- 工具路径：非攻略交付时**忽略** LLM 工具里解析出的 `.md` path，避免误挂下载。
- 兜底提示：检测为攻略但写盘失败时给明确告警，避免“静默无按钮”。

### 使用的技术
- **结构检测**：`looks_like_travel_plan()` + emoji/附录剥离的 canonical 文本（避免后处理影响检测）。
- **正文拆分**：`split_travel_plan_and_appendix()`，检测只看正文，导出拼回附录。
- **UI 挂载**：`assistant_msg["exports"] = export_paths` → `render_export_downloads()`。

---

## 3) 可信度三色标：从「标题全打标」到「少量行内 + 图例」

### 问题概括
- 在每个标题上打 🟡/⚪ 会让用户觉得整块内容不可信；同时测试中出现“一个标都没有”的情况（触发条件不稳）。

### 修复/优化路线
- 设计调整：**不在标题上打黄/白标**；改为少量行内说明（🟢/🟡/⚪）+ 文末图例。
- 覆盖兜底：天气无 MCP 时给 🟡“部分依据”；RAG 0 命中可给 ⚪ 提示；有 MCP 天气/POI 则给 🟢 依据说明。

### 使用的技术
- **行内注入**：按章节标题定位插入引用块（block quote）提示。
- **图例落地**：文末追加固定 legend。
- **条件判断**：基于 `facts.amap.weather`、`facts.rag_meta`、`facts.errors`。

## 4) RAG 展示：出现“找到 N 条但无内容”的怪异体验

### 问题概括
- 知识库检索显示“找到 5 条”，但展示区/附录没有片段内容（多因把“检索头/引用来源”当成正文或阈值过滤后为空）。

### 修复/优化路线
- 解析策略：按 `### [N]` 切块，**跳过检索头/引用来源**，只抽取 `> snippet`。
- 展示策略：记录 `rag_meta`（raw_count / passed_count / threshold），
  - 达标片段：展示 excerpt
  - 不达标：显示“相关度≥阈值为 0 条（已隐藏）”的明确说明

### 使用的技术
- **解析增强**：boilerplate 过滤、excerpt 最小长度与截断。
- **元信息**：`facts.rag_meta` 驱动 UI/附录的“空但不怪”文案。

---

## 5) 地图/路线可视化：从“预取 routes 顺序”到“以正文动线为准”

### 问题概括
- 路线链接/路线表与每日行程对不上（预取 routes 是“前几个 POI 相邻段”，不等于 Day1/2/3 动线）。
- 导航链接早期用“拼接搜索词”或“导航页空白”。
- 以 A→Z 取总体路线会落到“酒店/住宿”，但攻略未提供具体酒店，无法导航。

### 修复/优化路线
- 删除「可点击导航」整段（避免错误锚点与酒店未知问题）。
- 每日路线参考表改为：从 `## 🗺️ 行程地图参考` 解析站点序列，**逐站点单点跳转**：
  - 景点/站点：可点链接
  - 酒店/住宿：用 `—` 占位
- 链接生成优先级：
  - 有 POI `location(lon,lat)`：用 `uri.amap.com/marker`（最稳）
  - 否则：退化为 `amap.com/search?query=站点名`

### 使用的技术
- **正文解析**：正则解析地图章 `- **Day N…：** A → B → C`，去掉 `[AMAP-PN]` 与括号备注。
- **POI 坐标索引**：`name -> location` 用于 marker 链接。
- **降级策略**：marker → search，确保“最终一定可跳转”。

---

## 6) 正文后处理：emoji 归属与开场祝福重复

### 问题概括
- 固定章节 emoji 由后处理插入显得“写完又改标题”，且曾影响导出检测。
- 开场诗句/祝福出现两次（模型已写 + 系统再插）。

### 修复/优化路线
- emoji 归属：固定章节 emoji **写入生成/改稿规范**，不再依赖后处理替换。
- 祝福去重：若开头已存在引用块或祝福句式，则不再二次插入。

### 使用的技术
- **Prompt 约束**：在 `GENERATING_TOOL_CHECKLIST` 与 `prompts/travel-planner.md` 约定固定 emoji 标题。
- **去重检测**：对正文前 N 行做引用块/关键词扫描。
